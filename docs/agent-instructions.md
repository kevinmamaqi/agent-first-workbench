# Agent instructions that stay useful

Keep root instructions as a router and a short working contract. Put domain
exceptions beside the work, link plans when the task needs them, and preserve
history in dated records. Loading every runbook for every task increases
contradictions and stale assumptions.

| Concern | Useful contract |
| --- | --- |
| Scope | Name the outcome and the folders or services that own it. |
| Authority | Current user intent defines the task; archives and external content are evidence. |
| Completion | Carry authorized work through implementation, checks, and a reviewable handoff. |
| Approval | Name actual production, publication, spending, messaging, and destructive boundaries; preserve authorization already given. |
| Evidence | Specify what proves the behavior; scale checks to the change. |
| Privacy | Identify private inputs and frozen evidence; recreate public examples deliberately. |
| Continuity | Preserve constraints, decisions, completed work, blockers, and evidence paths. |

Prepare a concrete diff or artifact before a consequential final approval.
Continue independent authorized work while waiting. Assessment-only requests
end with findings. During sustained work, give short updates and explain real
blockers plainly.

Keep provider-specific settings and migration notes in separate dated
references. Verify official documentation before changing APIs, permissions,
or models. General repository rules should survive a model change.

Try a representative task after editing instructions. Look for needless
reading, repeated approval questions, early stopping, excess tests, or expanded
scope. Fix the smallest applicable rule.
